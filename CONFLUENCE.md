# BigQuery Metadata Manager - Описание сервиса

## Обзор

**BigQuery Metadata Manager** — веб-приложение для управления метаданными BigQuery таблиц и колонок. Сервис предоставляет удобный интерфейс для просмотра, редактирования и автоматической генерации описаний таблиц и колонок с использованием OpenAI API.

**URL:** https://tables-and-columns-description-web-gccuajx7eq-ew.a.run.app

**Проект:** guns-and-gangs  
**Регион:** europe-west1  
**Платформа:** Google Cloud Run

---

## Назначение

Сервис решает следующие задачи:

1. **Централизованное хранение метаданных** — все описания таблиц и колонок хранятся в BigQuery таблицах метаданных
2. **Визуальный просмотр и редактирование** — удобный веб-интерфейс для работы с метаданными
3. **Автоматическая генерация описаний** — использование OpenAI для создания детальных описаний на основе структуры таблиц и sample данных
4. **Синхронизация с BigQuery schema** — автоматическое обновление описаний в BigQuery metadata
5. **Поддержка всех таблиц** — отображение всех таблиц из BigQuery, даже если они отсутствуют в мета-таблицах

## Функциональность

### Основные возможности

#### 1. Просмотр метаданных

- **Иерархический вид:** Датасеты отображаются в свернутом виде (▶), при клике разворачиваются таблицы (▼)
- **Поиск:** Фильтрация таблиц и колонок по названию в реальном времени
- **Индикаторы статуса:** Визуальные маркеры для таблиц:
- **Зеленый** — описание есть и в мета-таблице, и в BigQuery schema
- **Желтый** — описание есть только в мета-таблице (таблица была пересоздана)
- **Красный** — нет описания ни в мета-таблице, ни в BigQuery schema
- **Отображение всех таблиц:** Показываются все таблицы из BigQuery, даже если их нет в мета-таблицах
- **Исключение шардированных таблиц:** Автоматически скрываются таблицы с суффиксами `_YYYYMMDD` или `_YYMMDD`

#### 2. Редактирование описаний

- **Таблицы:** Редактирование описания таблицы с сохранением в мета-таблицу и BigQuery schema
- **Колонки:** Редактирование описаний отдельных колонок
- **Массовое сохранение:** Кнопка "💾 Сохранить все описания колонок" для сохранения всех изменений одной операцией
- **Автосохранение:** Изменения автоматически синхронизируются с BigQuery schema

#### 3. Генерация через AI

##### Генерация описания таблицы:

1. **Получение информации о таблице:**
   - Получение списка всех колонок с типами данных
   - Подсчет чувствительных колонок (исключаются из sample данных)

2. **Получение sample данных:**
   - Использование `TABLESAMPLE SYSTEM (2 PERCENT)` для обычных таблиц
   - Использование `LIMIT` для VIEW и MATERIALIZED_VIEW
   - Исключение чувствительных колонок из выборки
   - Маскирование чувствительных значений перед отправкой в OpenAI
   - Получение первых 5 строк с максимум 3 примерами в промпте

3. **Формирование промпта:**
   - Название таблицы (маскируется, если чувствительное)
   - Общее количество колонок
   - Список колонок с типами данных (первые 20)
   - Sample данные (если доступны)
   - Строгие требования: минимум 3-4 предложения (100+ слов), детальное описание

4. **Генерация через OpenAI:**
   - Модель: GPT-4o-mini (по умолчанию)
   - Temperature: 0.7 (для более творческих ответов)
   - Max tokens: 500 (для детальных описаний)
   - Логирование промпта и ответа для отладки

5. **Автоматическое сохранение:**
   - Сохранение в мета-таблицу `table_descriptions`
   - Обновление описания в BigQuery schema
   - Возврат статистики: стоимость, токены, шаги выполнения

##### Генерация описания колонки:

1. **Получение информации о колонке:**
   - Тип данных колонки
   - Проверка на чувствительность (если чувствительная — sample значения не получаются)

2. **Получение sample значений:**
   - Для нечувствительных колонок: `SELECT DISTINCT` с `TABLESAMPLE SYSTEM (2 PERCENT)`
   - Маскирование значений перед отправкой в OpenAI
   - Максимум 5 примеров значений

3. **Генерация через OpenAI:**
   - Модель: GPT-4o-mini
   - Temperature: 0.5
   - Max tokens: 200
   - Описание: 1-2 предложения с бизнес-контекстом

4. **Автоматическое сохранение:**
   - Сохранение в мета-таблицу `column_descriptions`
   - Обновление описания в BigQuery schema колонки

##### Batch генерация описаний колонок:

- **Новый endpoint:** `POST /api/table/{dataset}/{table_name}/generate-all-column-descriptions`
- Генерирует описания для всех колонок таблицы, которые еще не имеют описаний
- Пропускает чувствительные колонки
- Пропускает колонки с уже существующими описаниями
- Сохраняет все описания batch операцией в мета-таблицу
- Возвращает статистику: количество созданных, пропущенных, общая стоимость

##### Информация о процессе:

- **Модальное окно:** Показывает детали процесса генерации перед запуском:
  - Что будет сделано
  - Какие запросы будут выполнены
  - Какие данные будут использованы
  - Подтверждение перед началом генерации

- **Отслеживание стоимости:** Отображение стоимости каждого запроса к OpenAI в реальном времени

#### 4. Безопасность

- **Маскирование чувствительных данных:**
  - Имена таблиц и колонок с чувствительными паттернами маскируются перед отправкой в OpenAI
  - Паттерны: pii, personal, ssn, password, credit card, payment, secret, token, auth, credential, email, phone, user_id, customer_id, address, ip_address, mac_address
  - Значения маскируются по паттернам: email → `***@***.***`, phone → `***-***-****`, ID → `***`

- **Параметризованные запросы:** Все SQL запросы используют параметризацию через `ScalarQueryParameter` для предотвращения SQL injection

- **Валидация входных данных:** Проверка имен таблиц и колонок перед обработкой

- **Исключение чувствительных колонок:** Чувствительные колонки не включаются в sample данные

## API Endpoints

### Веб-интерфейс

- `GET /` — Главная страница со списком таблиц (требует аутентификации)
- `GET /table/{dataset}/{table_name}` — Страница деталей таблицы с колонками (требует аутентификации)
- `GET /login` — Инициация OAuth логина
- `GET /auth/callback` — OAuth callback обработчик
- `GET /logout` — Выход из системы

### API для редактирования

- `POST /api/table/{dataset}/{table_name}/description` — Обновление описания таблицы
- `POST /api/table/{dataset}/{table_name}/column/{column_name}/description` — Обновление описания колонки

### API для генерации

- `POST /api/table/{dataset}/{table_name}/generate-description` — Генерация описания таблицы через AI
- `POST /api/table/{dataset}/{table_name}/column/{column_name}/generate-description` — Генерация описания колонки через AI
- `POST /api/table/{dataset}/{table_name}/generate-all-column-descriptions` — Batch генерация описаний всех колонок таблицы

**Все API endpoints требуют аутентификации через OAuth.**

## Производительность и оптимизация

### Оптимизации запросов

1. **Batch запросы вместо N+1:**
   - Получение всех таблиц одним запросом к `INFORMATION_SCHEMA.TABLES`
   - Получение всех описаний таблиц одним запросом к `TABLE_OPTIONS`
   - Получение количества колонок для всех таблиц одним запросом к `INFORMATION_SCHEMA.COLUMNS`

2. **Эффективное объединение данных:**
   - Использование словарей для быстрого поиска (O(1))
   - Минимальное количество запросов к BigQuery

3. **Кэширование схемы:**
   - Получение схемы таблицы один раз при загрузке страницы деталей
   - Использование `get_table()` API для получения описаний колонок

### Поддержка таблиц без метаданных

- Таблицы, существующие в BigQuery, но отсутствующие в мета-таблицах, отображаются автоматически
- При открытии деталей таблицы данные берутся из BigQuery schema, если метаданных нет
- Колонки объединяются из мета-таблицы и BigQuery schema

## Безопасность

### Реализованные меры

1. **SQL Injection Prevention**
   - Все запросы используют параметризацию через `ScalarQueryParameter`
   - Валидация имен таблиц и колонок
   - Использование `QueryJobConfig` для всех запросов

2. **Защита чувствительных данных**
   - Маскирование имен таблиц/колонок с чувствительными паттернами перед отправкой в OpenAI
   - Паттерны: pii, personal, ssn, password, credit card, payment, secret, token, auth, credential, email, phone, user_id, customer_id, address, ip_address, mac_address
   - Маскирование значений: email → `***@***.***`, phone → `***-***-****`, ID → `***`
   - Исключение чувствительных колонок из sample данных

3. **Аутентификация**
   - Google OAuth 2.0
   - Ограничение доступа по домену (oneupgames.gg)
   - Сессии с защищенным ключом
   - Все API endpoints защищены через `require_auth` dependency

4. **Secrets Management**
   - OpenAI API ключ хранится в Google Secret Manager (`analytics_table_desc_ai_creator`)
   - Не хранится в коде или переменных окружения напрямую
   - Доступ через Cloud Run secrets

5. **Обработка ошибок**
   - Try-finally блоки для гарантированной очистки временных таблиц
   - Graceful fallback при ошибках получения данных
   - Детальное логирование ошибок без раскрытия чувствительной информации

## Примеры использования

### Генерация описания таблицы

1. Откройте страницу таблицы
2. Нажмите "🤖 Сгенерировать через AI (с sample данными)"
3. В модальном окне просмотрите информацию о процессе:
   - Какие данные будут использованы
   - Какие запросы будут выполнены
   - Примерная стоимость
4. Нажмите "Продолжить генерацию"
5. Описание будет автоматически сгенерировано (минимум 3-4 предложения)
6. Результат будет сохранен в мета-таблицу и BigQuery schema

### Batch генерация описаний колонок

1. Откройте страницу таблицы
2. Используйте API endpoint `/api/table/{dataset}/{table_name}/generate-all-column-descriptions`
3. Или добавьте кнопку в UI для вызова этого endpoint
4. Все колонки без описаний будут сгенерированы автоматически
5. Результаты будут сохранены batch операцией

### Редактирование описания колонки

1. Откройте страницу таблицы
2. Найдите нужную колонку
3. Отредактируйте текст в поле описания
4. Нажмите "Сохранить" для отдельной колонки
5. Или используйте "💾 Сохранить все описания колонок" для массового сохранения
6. Изменения будут сохранены в мета-таблицу и BigQuery schema

### Просмотр таблиц без метаданных

1. Откройте главную страницу
2. Все таблицы из BigQuery отображаются автоматически
3. Таблицы без описаний помечены красным индикатором (❌)
